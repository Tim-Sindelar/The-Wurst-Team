# Agent and contributor rules

## Frontend (`frontend/`)

React 19, Vite, TypeScript, Mantine 9, Tailwind CSS 4, React Router, TanStack Query.

### Where things live

| Path | What it is |

| `src/theme/theme.tsx` | Mantine theme: type scale, radii, default props, variants, and which `ui-*` class each component part gets |

### Styling

1. **Tokens only.** No hex codes or raw pixel values for colour, spacing, radius, type or shadow in components or screens. Use token utilities: `bg-surface`, `text-text-muted`, `border-border-strong`, `rounded-card`, `shadow-card`, `text-title`, `p-4`. Tailwind's default palette, type scale, radii and shadows are removed, so only design tokens exist. If you need a new value, add a token to `src/styles.css` (dark in `@theme`, light under `[data-mantine-color-scheme='light']`).
2. **Mantine components are styled once, in the theme.** Each component gets `ui-*` classes in `src/theme/theme.tsx`, defined in `src/theme/components.css` with `@apply` inside `@layer components`. Screens pick a variant and never restyle a component's colours, borders or type. To change how a component looks, change `components.css`. Use a utility class on one instance only for layout (`flex-1`, `mt-2`, a card's status stripe).
3. **Layers decide who wins:** `theme < base < mantine < components < utilities`. Theme classes beat Mantine's defaults, and utilities beat theme classes. Don't use `!important`, and don't put utility classes in theme `classNames` (they would tie with screen classes).
4. **Tailwind for everything custom**: layout, spacing, one-off elements. No CSS modules and no new CSS files. Inline `style` is only for computed geometry (seat positions on the map).
5. **Write class names out in full.** Tailwind only finds literal strings, so `` `bg-seat-${state}` `` will not work. Put per-state classes in a lookup (`stateVar`, `stripeClass` in `src/domain/seat.ts`).
6. **Both themes.** Dark is the default; light is switched on the Profile screen (`ThemeSwitch`) through Mantine's colour scheme. Check every change in both.

### Components and variants

| Need | Use |
| --- | --- |
| Button | `Button` with `variant="primary"` (default), `"secondary"`, `"danger"`, `"quiet"` or `"map"` (32px text button floating on the room map). Links: `component={Link} to=...` |
| Icon-only button | `ActionIcon` with `variant="icon"` (default, 44px), `"map"` (32px map control) or `"camera"`. Always give it an `aria-label` |
| Card | `Card`; add `stripeClass[state]` for the 6px status stripe |
| Seat state chip | `SeatChip state=... [plain]` (Mantine `Badge` underneath) |
| In-page notice | `Alert` with `variant="info"` (default), `"warning"` or `"danger"` |
| Countdown | `TimerCard` (label, ticking time, progress bar) |
| Decision before an action | `DecisionSheet`: safe option left (outlined), action right; `actionTone="danger"` for end or cancel. Return the request's promise from `onConfirm`, so a double tap sends it once |
| Something happened | `notify(title, icon)` from `src/components/notify.tsx` for confirmations of what the user just did; server events through `describeEvent` in `src/domain/serverEvents.ts` (see "Real-time events"). Both float below the header and never move the page. `StatusBanner` remains for the booking screens' own banners |
| Toggle | `Switch` with a `label` |
| Text | `Title order={1}` is the 28px screen heading, `order={2/3}` the 20px title (add `text-heading` for a heading-sized `h2`). `Text size="sm"` for secondary text, `c="dimmed"` for muted. Section labels: `SectionLabel`. Timers: `text-timer tabular-nums` |
| Icons | `Icon` from `src/components/Icon.tsx` only (24px outline, 1.75 stroke). Add new icons there |
| Screen layout | `Screen` > `ScreenHeader` (back, title, requests bell) > `ScreenMain` > `ActionBar` |

Only two kinds of popup exist: the decision sheet and the notification banner. Don't add a third. Server events show the same banner through `@mantine/notifications` (themed in `theme.tsx`, `.ui-notifications`), so they are not a third kind. (The campus map's bottom sheets, `MapSheet`, use the decision sheet's frame for its settings and its room dashboard.) Errors on a screen are shown in place as a `danger` notice.

### Design rules that apply to code

- One primary (accent-filled) action per screen, in the `ActionBar`, full width.
- Never use colour alone: every state also has a label, icon or shape. Seat-state colours (`seat-*`) are only for seat state and availability.
- Touch targets are at least 44px. Use real links and buttons, never clickable `div`s. Label every icon-only control.
- Visible focus ring on everything focusable (Mantine's focus ring is mapped to `--color-focus`).
- Motion only on `transform` and `opacity`, 150 to 250ms, and respect reduced motion.
- Text never below 12px; long names (40+ characters) must wrap or truncate cleanly. Wrap names with `wrap-anywhere`, not `break-words`: only `anywhere` lets a long word shrink its grid or flex column.
- Phone first: below 480px (the `tablet` breakpoint) screens fill the full width with no side margins; from 480px up they are a centred 390px column. Don't stretch layouts wider. Headers and `SafeAreaTop` (Home) keep clear of the notch with `env(safe-area-inset-top)`.

### Campus map

- The map screen is full screen: the shared `ScreenHeader` (back, title) like every other screen, then the Leaflet map below it on the clean base map, a floor wheel on the right (one letter per floor: the letter the building in focus uses; the floor numbers themselves are untouched), and at the bottom Home's search box (`TextInput` with the search icon). Tapping it opens a fixed-height `MapSheet` bottom sheet (never a popup) with the same box focused and Home's results (`SpaceLists`, shared with Home): the Favourites, Recent and Most popular rows of space cards before anything is typed, the matching cards while typing. Tapping a card shows that space's workspace on the map (or opens its seat map when the map has none).
- The layers button at the top right (`map/ModeControl.tsx`) opens the "Map view" sheet with a three-step slider (`mapMode.ts`): **Study spaces** shows only the workspaces of the bookable study spaces (`GET /api/v1/spaces`, matched to the workspace containing its `map_room_id`, else by name and position), **Workspaces** shows every workspace with live rooms, **Campus** adds the ASVZ sport and mensa datasets. The same sheet has the 3D switch (on by default). The 3D stack always draws its visible edges faintly: the outline parts that change from one floor to the next, the lowest outline and the corners, minus those hidden behind the stack as seen from the south and above. There is no home button; tapping a campus area zone (`NavZones`) flies to it. The map opens on the Zentrum view (both campuses until the navigation zones have loaded). Everything else (other datasets, the time picker, detailed floor plans, other base maps, free rooms and UZH lists) is off and has no switch.
- Tapping a room, workspace or pin selects it and shows a card above the toolbar; its info button (or a second tap) opens the popup (a `MapSheet`). When the selection is a bookable study space (a workspace containing the space's `map_room_id`, else matched by name and position, or the ETH room itself), the card and the popup have a full-width "Open study space" button to the space's seat map, and the card has the favourite star next to its info button (`useFavourites`, the same favourites as Home). There are no hover tooltips.
- A workspace popup shows the booking status and photos of its ETH rooms, and a workspace that is also a mensa is drawn in the mensa's color with its menu in the popup, with live rooms and the mensa layer off too. The ETH room list is fetched the first time such a popup opens, the mensa items once the map is zoomed in.
- The map components keep their own markup and class names, styled in `src/campus-map/campus-map.css`, the one plain CSS file outside `src/theme`. Its colour names point at the design tokens. Colours drawn on the map come from the backend's map style (`GET /api/v1/map/style`). The ESLint React Compiler rules are off for this folder (the Leaflet layers rely on latest-value refs).
- All map data comes from the backend feature `backend/app/features/campus_map/` under `/api/v1/map`: workspaces, map style and navigation (Postgres), ETH room bookings, campus datasets and floor plans. The loaders in `src/campus-map/data/`, `datasets/repository.ts` and `map/minimalStyle.ts` call it through the generated client (`unwrap` in `data/api.ts`); floor plans and room photos are plain URLs under `MAP_API`. The map needs `make backend` running.
- The 3D view (`map/Floors3D.tsx`) stacks only the building group in focus. Groups are the buildings inside each building zoom zone, hardcoded in `map/buildingGroups.ts`; update that list when the zones change. Floor letters come from the room names and the scraper counts floor numbers per building, so once loaded the map shifts each zoned building's floor numbers to line up by letter with the zone's main building (`letterOffsets` in `buildingGroups.ts`, applied in `CampusMap` to the floor index, the workspaces and the room and mensa places): a floor shows every level with the same name, even at different heights (I counts as J). Every floor is drawn with its own outline (the group's levels on that floor merged), so the stack follows the real shape, and the floor with the `E` letters stays in place, so floors above it (the selected one too, with its workspaces and pins) are drawn further north. With 3D on, at every zoom, every group not stacked is drawn as its footprint only: the group's merged outline (all its floors together), flat in its real place, with no floor plan, workspaces or pins. The floor wheel then lists only the stacked group's floors (and hides without one); a group without the selected floor switches to its nearest one. In 2D too, only the selected floor's workspaces and pins are drawn. Room layouts show from the lowest zoom a building zone flies to (`roomZoom` in `MapView`).
- The workspaces, navigation zones and map style are JSON files in `backend/app/features/campus_map/map-data/`, imported into Postgres on start and on every deploy. There is no map admin or style editor in this app.
- The backend Docker build generates floor plans and workspace outlines into `/app/floors` and sets `MAP_FLOORS_DIR` to that directory. Outside Docker, floor plans are read from `scraper/floors` (built by `make map-floors`, not in git), or from the backend's `MAP_FLOORS_DIR`.

### Installable app (PWA)

- The app installs from https://02.hackathon.ethz.ch (and from each PR preview, as a separate app). The manifest uses relative URLs (`./`) and the worker registers at `BASE_URL`, so both work under `/pr/N/`. The manifest link has `crossorigin="use-credentials"` because the organisers' login proxy needs the session cookie.
- The service worker only exists in production builds. It caches the app shell on install, serves hashed `assets/` from the cache, goes to the network first for pages (offline: the cached `index.html`), and never touches `/api`. Production's worker leaves `/pr/` and `/ar/` alone. Every build gets a new worker that replaces the old one and its cache.
- Caddy serves `index.html`, `sw.js` and `manifest.webmanifest` with `no-cache`, so a deploy reaches installed apps on their next launch.
- The icon (`public/icons/icon.svg`, `public/favicon.svg`) is the seat mark: a desk with four seats, one free. The favicon is transparent and switches the free seat's green with the browser's colour scheme. In the app the name is `AppName` (mark, bold "Study", regular "Spaces"), used on Home and in the admin sidebar. After changing the icon, re-render `icon-192.png`, `icon-512.png` (also the maskable icon, so keep the artwork within the middle 80%) and `apple-touch-icon.png` (180px).
- `meta[name=theme-color]` follows the colour scheme (`--color-bg`), so the installed app's status bar matches the theme.

### Data and state

- Screens fetch with the generated TanStack Query helpers from `src/api/generated/` (`useQuery(listSpacesOptions())`, `useMutation(checkInMutation())`). Don't hand-write fetch calls or API types. The Vite dev server proxies `/api` to the backend on port 8000.
- The current booking comes from `useMyReservation()`. After any booking change call `useRefreshBooking()`'s function so Home, the seat map and the booking screens agree. Server timestamps go through `toClient()` so a wrong device clock can't skew countdowns.
- Failed calls are shown in place: use `apiProblem(error)` for the sentence, in a `danger` `Alert` or inside the `DecisionSheet`.
- Timing rules (check-in window, session length, extension windows, break allowance) are set in `backend/app/config.py` and read through `useRules()` (`GET /api/v1/rules`). Never hardcode them in the frontend.
- The seat map draws the room the admin laid out (`SpaceDetail.layout`, read with `savedLayout` and drawn with the admin `RoomScene` in read-only mode), so users see the same room, furniture and seat positions as the layout editor. `layoutSeats` in `src/domain/room.ts` places each seat at its layout object (`backendSeatId`). A space without a saved layout falls back to the stand-in floor plan there.
- Profile (opened from the bottom navigation) uses `/api/v1/me` through `useCurrentUser`. Its account-card pencil opens `/profile/edit`, where name and photo edits save together through the generated `updateMeMutation` and return to Profile. Leaving with unsaved edits uses `DecisionSheet`. Photo uploads allow 12 MiB and 16 megapixels; the circular drag/zoom preview uploads a square 256×256 PNG. The backend persists these in `user_profiles` without changing auth identity. Profile also has the Appearance card with the dark theme switch.
- Favourites live in `favourite_spaces` and come through `useFavourites()` (`/api/v1/me/favourites`). The star updates at once and rolls back if the call fails. Home shows them as their own row and filters by the search box (`filterSpaces`, `favouriteSpaces` in `domain/space.ts`).
- Recents live in `recent_spaces` and come through `useRecents()` (`/api/v1/me/recents`, newest first, at most 10). The backend records a space when the user books a seat there or checks in by scan; the migration seeds it from past reservations. Home shows swipeable rows under `SectionLabel`s: Favourites (`favouriteSpaces`), Recent (`spacesByIds`, newest first) and, always last, Most popular (`usePopular()`, `/api/v1/spaces/popular`: the five spaces with the highest share of seat time checked in over the last 7 days, measured against active seats and opening hours, so a new user sees something); an empty row is hidden. There is no all-spaces row: typing in the search box replaces the rows with a plain vertical list of matches. Home has no link to the map. Booking changes refresh it through `useRefreshBooking`.
- Home search uses `filterSpaces`, a dependency-free similarity search (`domain/similarity.ts`): it forgives typos, word order, accents and partial words, and lists the best match first.
- Space cards are plain surface cards. When a space has a photo it shows behind the text, always blurred 2px and dimmed with `bg-photo-scrim`, and the text on it uses `text-on-photo`. There are no placeholder photos. The photo is the first one on the room sheet of the space's ETH room (`map_room_id` read as an ETH room name): `SpaceSummary.photo_url`, a path to `/api/v1/map/eth/file` that `SpaceCard` puts under the API base URL. The backend (`campus_map/room_photos.py`) looks rooms up in the background and remembers them for a day; a list waits at most 1.5 s for rooms it hasn't seen, so a new space may get its photo on a later refetch. Rooms ETH has no sheet or photo for stay plain.
- The room screen (`/seats/:spaceId`, `SeatMapScreen`) is a full-bleed `SeatMap` under the header with nothing selected at first (or the seat in `?seat=`, when opened from a friend). Tapping a seat opens `SeatSheet` (a non-modal card at the bottom, not a third popup); its action opens the decision sheet to confirm. The `map` button "Choose any free seat" top right picks a random other free seat and is hidden while the user holds a seat. If the server answers `seat_unavailable` to a reservation (someone else was first), the sheet closes and a danger `Alert` "Seat X was just taken" with "Choose another seat" shows over the map; other errors stay inside the decision sheet.
- Check-in, extend and break scans go through `/scan?from=extend|break-start|break-end`. Each scan sends the scanned `qr_token` with its call (`check-ins`, or the reservation's `extend`, `break` or `return`), and the server refuses a code from any other seat (`wrong_seat`), so these steps can't be done away from the table. Printed seat QR codes are links, `<app address>qr?qr_token=…` (`domain/seatQr.ts`; the admin QR page sets the address, by default its own): opened from a phone camera, `/qr` (`SeatQrScreen`) looks the seat up through `GET /api/v1/seats/by-qr` and opens its seat map with the seat selected; the scan screen reads the token out of the link (`qrTokenFrom`), or takes a bare token. Demo QR tokens are printed by `make seed`. The camera feed fills the scan screen, dimmed outside the scan frame; there is no typed-code fallback. The camera needs `localhost` or HTTPS. In dev (`npm run dev`) the scan screen also has "Skip scan (demo only)", which reads the seat's code through the demo admin stub (`X-Demo-Admin`); it is compiled out of production builds.

### Friends and study groups

- Screens: Friends, Requests, Study group, New study group and Book together. The API calls a study group a party; the screens never say "party". Everything is live: there is no sample-data mode. `VITE_SOCIAL_ENABLED=false` hides the feature; a backend with social off shows an error in place.
- Data comes through `src/features/social/useSocial.ts`: `useFriends`, `usePeopleSearch`, `useGroups` (the group you're in, invitations, your last cancelled group), `useGroup`, `useRequestCount` (the bell) and `useSocialActions`, which runs one change at a time, keeps its error for the screen and refetches every query afterwards. Pure rules live in `groups.ts` and `seatTogether.ts` (tested in `tests/social-groups.test.ts`).
- A friend who shares their room and is checked in reports their room, seat and break (`FriendRoom`). They're marked everywhere the same way: an accent ring and a pin badge (a cup on a break) on their avatar (`PersonAvatar studying`). Tapping them on Friends opens their room's seat map with their seat selected (`friendSeatPath`, `/seats/:id?seat=`). On the seat map their seat shows their photo or initials ringed in the accent instead of its number (`SeatMap`'s `friends` prop), the header counts friends here, and the seat card names them. Pure helpers live in `studying.ts`.
- The bell (`RequestsBell`) is in every `ScreenHeader` and in Home's title row. It opens `/requests`, which holds study group invitations, friend requests and the requests you sent.
- One active group per person: an open group you joined, or a booked one while your seat from it is held or in use. A clash shows as one danger line on the invitation and disables Join.
- "Start a study group" always opens `/groups/new`; a cancelled group is offered there as "Use again" (name and people filled in), never shown as the current group.
- `/groups/:id/seats` is full screen like the seat map. The header shows the room and its free seats like the seat map, under it is Home's search box; while it's in use, matching rooms (`filterSpaces`, those the group fits in first) cover the map. Opening a room's seat map (`/seats/:id`) while you organize an open group someone joined redirects here with `?room=`. After each seat the picker moves to the next person without one. Once everyone has a seat, tapping a name (or their seat) selects that person and the next free seat tapped moves them; nobody's seat is ever cleared that way. Room results are Home's `SpaceLists` (rows before typing, matches while typing), with too-small rooms marked. Group seats show initials (`SeatMap`'s `people` prop). A `seat_unavailable` answer shows "A seat was just taken" over the map.
- Keep text minimal: no helper sentences, labels over explanations.

### Real-time events

- The app keeps one server-sent event stream (`EventSource`) open to `/api/v1/events` while signed in (`useServerEvents`, mounted once by `ServerEventNotifications` in `AppLayout`). It reconnects with backoff, and at once when the device is back online or the app is shown again. Each event refetches every query (`useRefreshBooking`) and shows a notification banner from `describeEvent` (`src/domain/serverEvents.ts`), which owns the wording, icon and the screen it links to. The banner's title is that link, stretched over the whole banner, so tapping anywhere opens it. The server sends a `ping` on connect and every 25 s when idle; it shows nothing. It is not a WebSocket because the organisers' edge proxy answers every WebSocket upgrade with a 502.
- Backend: `backend/app/features/events/`. `hub.publish(user_id, event)` is thread safe, so sync routes can call it. The stream is a `StreamingResponse` that authenticates with `get_current_user` like any route, so it needs the proxy's `X-User-Id`, or the default demo user in demo mode (browsers can't set `X-Demo-User-Id` on an `EventSource`). It sends `Cache-Control: no-transform`, so no proxy (Caddy's `encode` included) compresses and buffers it. The hub lives in memory: correct for the single uvicorn process we run. More workers would need Postgres `LISTEN/NOTIFY` behind the same `publish()`.
- Only committed changes notify: `SocialService` queues `(recipient, event)` in `self.events` and the router's `saved()` publishes after `commit()`. Never notify the user who acted, and never notify for retries that changed nothing.
- Events are pydantic models in `events/schemas.py`, joined in the `ServerEvent` union. `main.py` adds that union to the OpenAPI document (the stream route is left out of it), so `make generate` gives the frontend the `ServerEvent` type. To add an event: add its model to the union, append it where the change happens (published after commit), run `make generate`, then add its case to `describeEvent`.
- The Vite dev proxy and Caddy pass the stream through unbuffered (Caddy flushes `text/event-stream` at once); the service worker never touches `/api`. Backend tests read the stream generator directly, because the test client waits for a response to end.

### Code conventions

- Files that export components export only components (React Fast Refresh). Put contexts, hooks and constants in their own files.
- Dependencies are pinned to exact versions in `package.json`.
- Before pushing, run `npm run lint`, `npm run typecheck`, `npm test` and `npm run build` in `frontend/`. For visual changes, check the screen in both themes.
